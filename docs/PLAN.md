# OptiMaxing v2 — план большого расширения

Статус: черновик плана, утверждён порядок «сначала план, потом реализация».
Дата составления: 2026-08-10.

Текущее состояние (v1, коммит 7f781b8): ~59 фиксированных твиков + динамические
Run-записи, 3 вкладки (Здоровье системы / Твики / Инструменты и советы), 23 теста.

---

## 0. Анализ конкурентов — что они умеют, а мы нет

### Мониторинг и аналитика (наша самая слабая зона)

| Инструмент | Ключевая возможность, которой у нас нет |
|---|---|
| HWiNFO64 | Датчики в реальном времени: температуры CPU по ядрам, GPU hotspot/VRAM temp, обороты кулеров, вольтажи, энергопотребление, текущие частоты, флаги троттлинга, логирование в CSV |
| CPU-Z | Идентификация железа: степпинг/кодовое имя CPU, кэши L1/L2/L3, тайминги RAM (CL-tRCD-tRP-tRAS), SPD по слотам, наличие и активность XMP/EXPO, чипсет и версия BIOS |
| GPU-Z | Модель GPU, объём и тип VRAM, ширина шины, версия драйвера, состояние Resizable BAR |
| CrystalDiskInfo | SMART по каждому диску: здоровье в %, часы работы, записано ТБ (TBW), температура, счётчики переназначенных секторов |
| HWMonitor | Тот же класс данных, что HWiNFO, но проще: min/max/current по каждому сенсору |
| LatencyMon | DPC-задержки в разрезе драйверов — показывает, какой драйвер вызывает микрофризы |
| CapFrameX / PresentMon | Фреймтайминги, 1% и 0.1% low, анализ стуттера |

### Управление системой

| Инструмент | Ключевая возможность, которой у нас нет |
|---|---|
| Autoruns | ВСЕ точки автозапуска, а не только Run-ключи: папки автозагрузки, задачи планировщика, службы, драйверы, Winlogon, расширения проводника, кодеки, обработчики контекстного меню. И удаление, а не только отключение |
| Process Explorer / Диспетчер задач | Живой список процессов: CPU/RAM/диск/сеть по процессу, завершение, приоритет, привязка к ядрам (affinity), путь к файлу, издатель |
| Process Lasso | Постоянные правила приоритета/affinity, ProBalance, авто-переключение схемы питания при запуске игры |
| Revo Uninstaller | Список установленных программ, удаление + зачистка остатков в реестре и файлах |
| O&O ShutUp10++ | ~150 переключателей приватности, у каждого — индикатор реального текущего состояния системы и «рекомендуемое» значение |
| CCleaner | Очистка + менеджер автозапуска + деинсталлятор в одном |
| WinUtil (Chris Titus) | Пресеты, установка софта, управление обновлениями Windows |

### Выводы: приоритетные пробелы OptiMaxing

1. **Нет информации о железе вообще** — ни GPU, ни материнки, ни BIOS, ни модулей
   RAM, ни моделей дисков. Сейчас только ОС, имя CPU из реестра, объём RAM и
   свободное место на дисках.
2. **Нет живых датчиков** — ни температур, ни частот, ни оборотов, ни нагрузки.
3. **Нет менеджеров** — процессов, служб (кроме 6 захардкоженных), полного
   автозапуска, установленных программ.
4. **Твики только bool** — нельзя выбрать значение (например Win32PrioritySeparation
   26 против 2A), только «применить/откатить» фиксированный вариант.
5. **Сканирование состояния неполное** — состояние читается через собственные
   абстракции, но не показывается «как есть в системе» для настроек, которые
   OptiMaxing не умеет менять.
6. **UI**: рывковый скролл, слабо видно что выбрано.

## Этап 1 — UI-фундамент

Цель: приложение должно приятно ощущаться. Быстро и сразу заметно.

- **Плавный скролл.** Сейчас `ListBox` скроллит по элементам (`CanContentScroll=True`),
  из-за чего за один тик колеса проскакивает целая карточка. Ставим
  `ScrollViewer.CanContentScroll="False"` для пиксельного скролла + собственное
  поведение инерции/шага колеса. Проверить, что виртуализация не ломается на
  больших списках (процессы/службы будут на сотни строк — там оставить
  виртуализацию с пиксельным скроллом через `VirtualizingPanel.ScrollUnit="Pixel"`).
- **Подсветка выбранного.** Выбранные твики получают явный фон + акцентную левую
  полосу + жирный чекбокс. Счётчик «Выбрано: N» в футере, живой.
- Выделение строки целиком кликом (не только по чекбоксу).

## Этап 2 — «Здоровье системы» → полноценная аналитика

Цель: заменить бедную страницу на то, ради чего открывают HWiNFO/CPU-Z/GPU-Z.

### 2.1 Инвентарь железа (WMI, разово при старте)

- **CPU**: модель, ядра/потоки, базовая частота, сокет, кэш L2/L3, виртуализация
- **GPU** (все адаптеры): модель, объём VRAM, версия и дата драйвера
- **Материнская плата**: производитель, модель, чипсет
- **BIOS/UEFI**: версия, дата (старый BIOS — повод обновить ради Resizable BAR/AGESA)
- **RAM по модулям**: слот, объём, частота реальная против заявленной SPD,
  производитель, парт-номер → отсюда автоматический вывод «XMP не включён»
- **Диски**: модель, интерфейс, тип (SSD/HDD/NVMe), объём

### 2.2 Живые датчики (LibreHardwareMonitorLib — утверждено)

Подключаем NuGet `LibreHardwareMonitorLib`. Даёт то же, что HWiNFO:
температуры CPU (пакет и по ядрам), GPU (ядро/hotspot/VRAM), частоты, нагрузку,
обороты кулеров, энергопотребление, температуры накопителей.

- Обновление по таймеру (1 сек), только пока вкладка открыта — не жрать CPU в фоне
- Мини-графики истории за последние ~60 секунд
- Фиксация max за сессию (как в HWMonitor)
- **Важно**: библиотека ставит ring0-драйвер для доступа к сенсорам. Это надо
  явно оговорить в UI («для чтения датчиков нужен драйвер мониторинга») и
  корректно отработать случай, когда драйвер не поднялся — не падать, а
  показать «датчики недоступны» и остальную информацию.

### 2.3 SMART по дискам

Здоровье в %, часы работы, записано ТБ, температура, переназначенные секторы.
Через WMI `MSStorageDriver_FailurePredictData` + `Win32_DiskDrive`.

### 2.4 Итоговая оценка и узкие места

Автовыводы вместо сырых цифр: «RAM работает на 2133 МГц при заявленных 3200 —
не включён XMP», «SSD заполнен на 94% — падает скорость записи», «GPU-драйвер
от 2024 года», «CPU троттлит при 97°C», «диск C: — HDD, игры будут долго
грузиться».

## Этап 3 — новые вкладки-менеджеры

### 3.1 Вкладка «Автозапуск» (Autoruns-parity)

Все источники в одном списке с фильтром по типу:
- Run/RunOnce (HKCU + HKLM, включая Wow6432Node)
- Папки автозагрузки (пользователя и общая)
- Задачи планировщика с триггером «при входе/при старте»
- Службы с автозапуском
- Драйверы (boot/system start)
- Winlogon (Shell, Userinit), расширения проводника

Действия: **отключить** (обратимо, с бэкапом) и **удалить** (необратимо, с
подтверждением). Показывать: имя, издатель, путь, статус подписи файла,
существует ли файл вообще (битые записи — кандидаты на удаление).

### 3.2 Вкладка «Процессы»

Живой список: имя, PID, CPU %, RAM, путь, издатель. Действия: завершить,
завершить дерево, приоритет, affinity, открыть папку. Сортировка по любой
колонке. Подсветка процессов с высоким потреблением.

### 3.3 Вкладка «Службы»

Все службы системы (не 6 захардкоженных): имя, отображаемое имя, состояние,
тип запуска, описание. Действия: старт/стоп/перезапуск, смена типа запуска.
Пометки «безопасно отключить для игр» на основе нашего каталога знаний.

### 3.4 Вкладка «Программы»

Список установленного из реестра Uninstall (HKLM + HKCU + Wow6432Node):
имя, издатель, версия, размер, дата установки. Запуск штатного деинсталлятора.
Подсветка потенциального мусора (тулбары, «оптимизаторы», bloatware вендоров).

## Этап 4 — твики: системное сканирование и настраиваемость

### 4.1 Настраиваемые твики (не только вкл/выкл)

Новый тип `ChoiceOptimization`: у твика есть набор вариантов значений с
описанием каждого, пользователь выбирает. Кандидаты:
- `Win32PrioritySeparation`: 26 (низкая задержка) / 2A (стабильность) / 2 (дефолт)
- Планировщик игр `SystemProfile\Tasks\Games`: Scheduling Category High/Medium
- `TdrDelay`: 8/10/60 сек
- `NetworkThrottlingIndex`: выкл / 10 / 70
- Схема питания: Сбалансированная / Высокая производительность / Максимальная
- Размер файла подкачки

### 4.2 Настоящее системное сканирование

Показывать реальное текущее значение ключа/службы «как есть в системе», даже
если оно не совпадает ни с «применено», ни с «дефолт» — сейчас такие случаи
схлопываются в `Modified` без деталей. Добавить в карточку строку
«Сейчас в системе: <значение>».

### 4.3 +30-50 новых твиков

- **Латентность/ввод**: MSI-режим для GPU, Scheduling Category, SystemResponsiveness,
  отключение Nagle (TcpAckFrequency/TCPNoDelay), HPET-политика,
  `Win32PrioritySeparation`, отключение Power Throttling
- **Сеть**: автотюнинг TCP, RSS, отключение энергосбережения сетевого адаптера,
  DNS-over-HTTPS, сброс метрик
- **GPU**: TdrDelay, отключение GPU-предзагрузки, кэш шейдеров **AMD**
  (`%LOCALAPPDATA%\AMD\DxCache`, `GLCache`) — сейчас есть только NVIDIA-пути
- **Приватность (до уровня O&O ShutUp10)**: ещё ~20 переключателей телеметрии,
  разрешений приложений (камера/микрофон/местоположение в фоне), Edge/OneDrive
- **Обслуживание**: очистка старых точек восстановления, `WinSxS` (DISM),
  журналы событий, дампы, кэш эскизов, Prefetch
- **Windows Update**: отложить функциональные обновления, отключить
  авто-перезагрузку, P2P-раздачу обновлений

## Порядок и принципы

1. Этап 1 → 2 → 3 → 4, каждый этап отдельным коммитом с прогоном тестов.
2. Все новые системные обращения — через DI-абстракции (`ISystemInfoProvider`-
   стиль) с фейками, чтобы тесты не трогали реальную машину. Это правило уже
   выдержано в v1 и не должно ломаться.
3. Никакого текстового парсинга локализованного вывода команд — только
   реестр, enum'ы, коды возврата, WMI-поля. Дважды обжигались (PowerPlan,
   ScheduledTask).
4. Удаление чего-либо — только необратимая операция с явным подтверждением
   и предварительным бэкапом того, что вообще можно сохранить.
5. Ничего не выдаём за проверенное, если не прогнали. Пункты, требующие
   реальной машины/ВМ, помечаются как непроверенные.

## Риски

- **LibreHardwareMonitorLib ставит ring0-драйвер** — на неподписанном
  приложении это дополнительный повод для антивируса ругаться. Плюс на
  некоторых системах драйвер не поднимется (Secure Boot/политики). Обязателен
  безопасный фолбэк.
- **Процессы/службы/автозапуск — это операции с реальным риском.** Удаление
  записи автозапуска или остановка службы может сломать вход в систему.
  Нужны те же гейты, что для Advanced-твиков (точка восстановления), и
  чёрный список критичных служб, которые вообще нельзя трогать.
- **Объём.** Это фактически v2 приложения, а не доработка. Реалистично —
  несколько больших заходов, а не один.
