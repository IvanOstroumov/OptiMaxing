# Релиз OptiMaxing: сборка и дистрибуция

## Сборка exe

```
dotnet publish src\OptiMaxing.App\OptiMaxing.App.csproj -c Release -r win-x64 --self-contained true -o publish
```

Даёт один self-contained файл `publish\OptiMaxing.exe` (рантайм .NET 8 и нативные
библиотеки WPF вшиты внутрь, `PublishSingleFile`+`IncludeNativeLibrariesForSelfExtract`
в csproj) — пользователю не нужен установленный .NET.

## Установщик (Inno Setup)

Скрипт: `installer\OptiMaxing.iss`. Собирается через Inno Setup 6 (ISCC.exe),
которого нет на этой машине — установи с https://jrsoftware.org/isinfo.php,
затем:

```
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer\OptiMaxing.iss
```

Результат: `installer\output\OptiMaxing-Setup-1.0.0.exe`. Установщик требует
элевации (как и сам OptiMaxing.exe — см. `app.manifest`, `requireAdministrator`,
без этого твики реестра/служб не применить), не удаляет пользовательские
данные (JSON backup / restore-point tracking в `%LOCALAPPDATA%`) при
деинсталляции — чтобы откат прошлых твиков оставался возможен после
переустановки.

## Подпись кода (решение M9)

**Не подписано.** OptiMaxing трогает реестр, службы, запланированные задачи —
без EV/OV сертификата Windows SmartScreen будет показывать
"Windows защитила ваш компьютер" при первом запуске неподписанного exe и
установщика. Варианты на будущее:

- **EV-сертификат** — SmartScreen репутация появляется почти сразу, но
  дороже и требует аппаратного токена/облачного HSM (сертификат нельзя
  просто "иметь файлом").
- **OV-сертификат** — дешевле, но репутация SmartScreen строится постепенно
  по мере накопления загрузок с этой подписью; первые релизы всё равно
  будут триггерить предупреждение.

Решение отложено до появления сертификата (вне контроля кода — организационный
вопрос: покупка, верификация организации). Когда сертификат будет, подписать
и `publish\OptiMaxing.exe`, и собранный `Setup.exe`:

```
signtool sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 /a publish\OptiMaxing.exe
signtool sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 /a installer\output\OptiMaxing-Setup-1.0.0.exe
```

До тех пор: README для пользователей должен явно предупреждать про
SmartScreen и объяснять "Подробнее → Выполнить в любом случае" — это не баг,
а следствие отсутствия платной подписи, а не признак того, что exe
скомпрометирован.

## VM-тестирование (чек-лист, не выполнено — нет доступа к чистой ВМ отсюда)

Перед публикацией релиза стоит прогнать на чистой Win11 ВМ (без прежних
запусков OptiMaxing):

- [ ] Установка через Setup.exe от имени администратора проходит без ошибок
- [ ] Первый запуск: баннер "точки восстановления нет" отображается,
      кнопка создания точки восстановления работает
- [ ] Sканирование (`ScanCommand`) не падает и корректно определяет
      Applied/NotApplied для чистой системы (ожидается почти всё NotApplied)
- [ ] Применение Safe-пресета, затем полный откат — система возвращается
      в рабочее состояние (в частности explorer.exe не падает после твиков
      Explorer/реестра)
- [ ] Деинсталляция через "Установка и удаление программ" не оставляет
      `Program Files\OptiMaxing`, но оставляет `%LOCALAPPDATA%` с бэкапами
- [ ] Вкладка "Инструменты и советы": кнопки "Скачать" открывают браузер
      на верных URL для утилит, которых на ВМ нет

Этот пункт остаётся открытым до тестового прогона на реальной ВМ.
